## Тестування сервісів

Тестовий проєкт `SubscriptionServiceTests` містить повний набір юніт-тестів, що покривають усю бізнес-логіку обох сервісів.

### 1. MemberServiceTests (Тести для `MemberService`)

Цей клас тестів перевіряє логіку, пов'язану з отриманням інформації про учасників.

* **`Метод IsActive`**
    * Використано `[Theory]` та `[InlineData]` для одночасної перевірки трьох сценаріїв:
        1.  Учасник існує і активний (очікується `true`).
        2.  Учасник існує, але неактивний (очікується `false`).
        3.  Учасник не існує (очікується `false`).

* **`Метод GetMember`**
    * Перевірено коректне повернення існуючого учасника (`Assert.NotNull` та `Assert.Equal`).
    * Перевірено повернення `null` при запиті неіснуючого учасника (`Assert.Null`).

* **`Метод GetAllActiveMembers`**
    * Перевірено, що список містить *лише* активних учасників (`Assert.NotEmpty`, `Assert.Contains`).
    * Перевірено, що список *не* містить неактивних учасників (`Assert.DoesNotContain`).
    * Перевірено, що кількість відфільтрованих учасників не дорівнює загальній (`Assert.NotEqual`).
    * Перевірено повернення порожньої колекції, якщо активних учасників немає (`Assert.Empty`).

### 2. SubscriptionServiceTests (Тести для `SubscriptionService`)

Цей клас тестів перевіряє складнішу бізнес-логіку поновлення та деактивації підписок.

* **`Метод RenewSubscription`**
    * **Успішний сценарій:** Перевірено повернення `true` (`Assert.True`), зміну статусу учасника та те, що методи `_repo.Update` і `_notify.SendNotification` були коректно викликані (`Verify(..., Times.Once)`).
    * **Неуспішна оплата:** Перевірено повернення `false` (`Assert.False`) та те, що дані *не* були збережені і сповіщення *не* було надіслано (`Verify(..., Times.Never)`).
    * **Неіснуючий учасник:** Перевірено, що сервіс генерує очікуваний виняток `ArgumentException` (`Assert.Throws`).

* **`Метод DeactivateExpiredMembers`**
    * **Одиночна деактивація:** Перевірено, що статус простроченого учасника змінюється на `false` (`Assert.False`) і що метод `Update` викликається з коректними даними, використовуючи предикат (`It.Is<Member>(...)`).
    * **Пакетна деактивація:** Додано окремий тест, що перевіряє коректну деактивацію *кількох* прострочених учасників та виклик `Update` і `SendNotification` точну кількість разів (`Verify(..., Times.Exactly(2))`).
    * **Відсутність прострочених:** Перевірено, що жодні методи не викликаються (`Verify(..., Times.Never)`), якщо всі підписки активні.

## Реалізовані типи перевірок

Відповідно до завдання, проєкт реалізує понад 10 різних типів перевірок з xUnit та Moq:

* `[Fact]` — для простих тестів.
* `[Theory] / [InlineData]` — для параметризованих тестів.
* `Assert.True` / `Assert.False` — для булевих перевірок.
* `Assert.Equal` / `Assert.NotEqual` — для порівняння значень.
* `Assert.Null` / `Assert.NotNull` — для перевірки на існування об'єкта.
* `Assert.Contains` / `Assert.DoesNotContain` — для перевірки наявності у колекції.
* `Assert.Empty` / `Assert.NotEmpty` — для перевірки порожності колекції.
* `Assert.Throws` — для перевірки винятків.
* `Verify(..., Times.Once)` — перевірка, що метод викликано 1 раз.
* `Verify(..., Times.Never)` — перевірка, що метод не викликано.
* `Verify(..., Times.Exactly(n))` — перевірка точної кількості викликів.
* `It.IsAny<T>()` — для імітації аргументу будь-якого значення.
* `It.Is<T>(predicate)` — для перевірки, що аргумент відповідає складному предикату.
